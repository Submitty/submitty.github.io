Release [v26.10.01](https://github.com/Submitty/Submitty/releases/v26.10.01)
changes the Apache and nginx configuration that Submitty ships.
The installer does not update existing configuration files,
so make these edits by hand.


### Apache: turn off FastCGI connection reuse

In `/etc/apache2/sites-available/submitty.conf`, change
`enablereuse=on` to `enablereuse=off`:

```apache
<Proxy "fcgi://localhost/" enablereuse=off max=20>
</Proxy>
```

Then restart Apache:

```sh
sudo systemctl restart apache2
```

Use restart, not reload. A reload waits for requests that are already
stuck, so it won't free PHP-FPM workers that are already held.

With reuse on, idle connections can hold every PHP-FPM worker, and
bursts of requests hang. Examples are office hours queue updates and
git pushes near a deadline.
See [#13475](https://github.com/Submitty/Submitty/pull/13475).


### nginx: forward only the websocket cookie

In the `location /ws` block of `/etc/nginx/sites-available/submitty.conf`,
add this line after `proxy_set_header Host $host;`:

```nginx
proxy_set_header Cookie "submitty_websocket_token=$cookie_submitty_websocket_token";
```

Then reload nginx:

```sh
sudo systemctl reload nginx
```

This stops cookies that other sites set on the same domain from pushing
the websocket handshake past the websocket server's 4096-byte limit.
See [#13393](https://github.com/Submitty/Submitty/pull/13393).
